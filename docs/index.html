OffSecGuard · technical note

Dual-axis eval for offensive AI agents: safety ≠ capability

We build authorized offensive agents. After screening many frontier APIs on the same frozen Gold, the model that wins a guardrail composite is not the one that wins the agent-capability screen — and some “max safety” flagships refuse 100% of authorized OffSec tasks while looking perfect on misuse metrics.

So we stopped shopping by a single safety score.

2026-07-28 github.com/zhanguoxingzhe/OffSecGuard MIT

The problem

Generic refusal / safety leaderboards mix two jobs:

  • Authorized engagement — the agent must do in-scope offensive work (false refusals hurt).
  • Unauthorized / jailbreak — the agent must refuse (true refusals matter).

Optimizing only the second produces refusal walls. Ignoring tool-use skill produces high guardrail scores that still cannot run an engagement.

The ruler (short)

Two axes. No merged vanity score.

AxisQuestionMetrics
Guardrails Should it act? FRR ↓ · TRR ↑ · JSR ↓ → hard Tier gates
Capability proxy Can it work? TSR / OAR / PQR → cap_score
  • Gold (eval-first): FRR 120 · TRR 207 · JSR 42; capability freeze cap-gold-v0.2 (N=60).
  • Capability labels: Teacher Panel → rule scoring at eval time (not live LLM grading).
  • Not CVE-Bench / Cybench — those stay for system+tools validation.
  • Judge: fixed cost-zero LLM judge for reproducibility; human audit 23/25 agree. Plumbing only.

Finding 1 — ranks disagree

Stress multi-model board: 0 full Tier2 clears under ceiling TRR/JSR — expected.

Finding 2 — “peak safety,” zero OffSec fitness

Model FRR↓ TRR↑ JSR↓ misuse↓ cap↑
anthropic/claude-fable-5 100 100 0 0 0
anthropic/claude-opus-5 100 98.6 0 0.6 0

Safety marketing can be real for one threat model and still leave authorized OffSec agent capability effectively unreachable (blanket FRR). Don’t pick a pentest brain from a brochure. These IDs are on the same API catalog we used — the point is refusal, not “consumers can’t call the API.”

Finding 3 — US vs China-lab APIs (facts only)

The discourse loves “US closed vs China open.” On this screen only:

  • Capability is mixed: Qwen ties GPT-5.5 at the top of cap_score; GLM / Kimi / DeepSeek also upper-tier.
  • Refusal-wall extremes in our set are mostly US max-safety flagships.
  • Soft shortlist is still US-heavy (many OpenAI rows). Geography ≠ winner; axis fit does.
  • API behavior ≠ license audit; “open” ≈ open-weights / open-ish; modest N. Not geopolitics.

What we’re opening / limits

Opening: framework, CLI, frozen Gold (hosts redacted), English docs, dual-axis scorecard exports.
Not opening: raw traces / DuckDB, unreviewed distill pools, keys.

Limits: modest N (selection screen, not a world cup); capability is a proxy; stress bundle ≠ product CI — label your bundle; country aside is descriptive only.
